# Kafka UI (Quarkus + htmx) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone, Kafbat-looking web UI for one Strimzi Kafka cluster + Apicurio Registry 3, where Kafka (not the UI) decides what the user may do.

**Architecture:** One Quarkus app. Server-rendered Qute templates + htmx (SSE extension for tail/search streaming). Feature packages (topics, messages, produce, groups, acls, schemas, overview) sit on three shared layers: `security` (mode, TLS material, current credentials), `kafka` (per-credential AdminClient/consumer/producer factory, error translation, permissions) and `registry`+`serde` (Apicurio v3 REST client, schema cache, format detection/decoding).

**Tech Stack:** Java 21, Quarkus (latest stable 3.x platform), quarkus-rest + quarkus-rest-qute, quarkus-oidc, quarkus-kafka-client (for kafka-clients + Dev Services in tests), io.strimzi:kafka-oauth-client (latest), org.apache.avro:avro (version managed by Quarkus BOM or latest 1.12.x), tech.allegro.schema.json2avro:converter 0.2.15, BouncyCastle bcpkix-jdk18on (test scope only, for generating test certificates), Caffeine (via quarkus-cache's dependency or com.github.ben-manes.caffeine directly), htmx 2.0.4 + htmx-ext-sse 2.2.2 + highlight.js 11.9.0 vendored as static files. Tests: JUnit 5, rest-assured, AssertJ, WireMock (org.wiremock:wiremock-standalone), Testcontainers (Apicurio 3), Quarkus Dev Services (Kafka, Keycloak).

**Spec:** `docs/superpowers/specs/2026-10-22-kafka-ui-design.md`

## Global Constraints

- Base package `se.afshin.yavari.kafka.ui`; Maven groupId `se.afshin.yavari`, artifactId `kafka-ui`.
- Config prefix `kafka-ui` (env vars `KAFKA_UI_*`). Mode: `kafka-ui.mode` = `mtls` | `oidc`.
- Only write operations: **produce** and **reset consumer group offsets**. No create/delete/alter of topics, topic config, ACLs, schemas; no delete group; no purge.
- Apicurio Registry **v3 only** (`/apis/registry/v3`). Registry decoding: **Avro and JSON Schema**. No Protobuf anywhere.
- One cluster per installation. No Kafka Connect, no KSQL.
- No UI-side authorization model. Lists show what Kafka returns; buttons disabled from Kafka `authorizedOperations`; denials shown as plain-language messages, never stack traces.
- mTLS mode: no login, client cert used for Kafka AND the Apicurio proxy, permanent banner "mTLS mode – no login, all users share the UI certificate's permissions" (test environments only).
- OIDC mode: Keycloak authorization-code login; the user's access token is forwarded as-is (no token exchange) to Kafka (SASL_SSL OAUTHBEARER, Strimzi client) and to the Apicurio proxy (`Authorization: Bearer`).
- Certificates are files (mounted secrets): client cert, client key, CA bundle, all PEM; paths configurable; reloaded on change.
- OIDC mode: schema cache keyed per user; 401/403 from the proxy is never cached as "not found".
- UI copy in English; Kafbat-like layout: left sidebar (Dashboard, Brokers, Topics, Consumers, Schema Registry, ACLs), tables, detail pages with tabs.
- Every code change ships with unit tests (`./mvnw test` green before each commit).

## Review Focus

1. A CA bundle with several certificates (intermediates + roots) → all must be trusted, not just the first. Client keys are always PKCS#8 (`BEGIN PRIVATE KEY`, guaranteed by the ops team's extraction); any other key format fails fast with a clear message naming the file. Tests in Task 2.
2. A user regex with catastrophic backtracking (e.g. `(a+)+$` on a 50 kB value) → search keeps going, the message counts as "regex timed out", and the user sees how many timed out. Test in Task 9.
3. A payload starting with 0x00 that is not Apicurio framing (or an id the registry doesn't have) → falls back to JSON/XML/text/hex with an explanation, never an error page. XML with a DOCTYPE/external entity must not resolve entities. Tests in Task 7.
4. Access token expires during a long tail/search → the stream reconnects with the refreshed token or ends with "Your session expired – reload", never hangs silently. Test in Task 14.
5. Kafka denies an operation (TopicAuthorizationException, GroupAuthorizationException, ClusterAuthorizationException, SaslAuthenticationException) on any page → page renders a friendly message naming the resource. Tests in Task 4 and Task 13.

### Task 7: Automatic decoding with explanation

**Files:**
- Create: `serde/Format.java`, `serde/Decoded.java`, `serde/AvroCodec.java`, `serde/XmlPretty.java`, `serde/MessageDecoder.java`
- Test: `serde/MessageDecoderTest.java`, `serde/AvroCodecTest.java`, `serde/XmlPrettyTest.java`

**Interfaces:**
- Consumes: `SchemaCache.get`, `WireFormat`
- Produces:
  - `record Decoded(Format format, String text, String explanation, Optional<SchemaRef> ref)`
  - `MessageDecoder`: `Decoded decode(Credentials, byte[] data, Headers headers, boolean isKey)`; `Decoded decodeAs(Credentials, byte[] data, Headers headers, boolean isKey, Format forced)` (manual override; AVRO/JSON_SCHEMA forced still need a schema ref and explain if none).
  - `AvroCodec`: `String toJson(Schema writer, byte[] body, boolean jsonEncoded)` (plain JSON, no union wrapping, via allegro `JsonAvroConverter`), `byte[] fromJson(Schema, String json)` throwing `AvroJsonException(String fieldPath, String message)`; `Schema parse(RegistrySchema)` resolving references.
  - `XmlPretty`: `Optional<String> pretty(String text)` (DTDs disallowed: `disallow-doctype-decl`, no external entities).

Algorithm (key and value separately):
1. `null` → `NULL` ("Tombstone (null)"); length 0 → `EMPTY`.
2. Header ref → lookup. `Found` → decode by type (AVRO via `AvroCodec`, honouring `encoding` header; JSON_SCHEMA → pretty JSON of the full payload, or of the body after framing if framed). Explanation: `"Avro – schema {group}/{artifact} v{version}, {globalId|contentId} {id} from header"`.
3. Else each payload candidate in order; first `Found` whose decoding succeeds wins (explanation says `"from payload (4-byte contentId)"` etc.).
4. `Denied` at any step → continue fallback, explanation prefixed `"No permission to read schema {kind} {id} – "`. `Unavailable` → prefix `"Schema registry unavailable – "`.
5. Fallback: valid UTF-8? → JSON (Jackson parse, pretty) → XML (`XmlPretty`) → TEXT. Not UTF-8 → HEX (first 4 KB, hexdump style).
6. A decoding exception never escapes; it becomes a fallback with the reason in the explanation.

**Interfaces:**
- Consumes: `KafkaClients.newConsumer`, `MessageDecoder`, `KafkaUiConfig.search()`
- Produces:
  - `record SearchRequest(String topic, Set<Integer> partitions /* empty = all */, Instant from, Instant to, Optional<Long> fromOffset, Optional<Pattern> keyRegex, Optional<Pattern> valueRegex)`
  - `sealed interface SearchEvent permits Match(MessageView), Progress(long scanned, long matched, long regexTimeouts), Done(long scanned, long matched, long regexTimeouts, String stopReason)`; `stopReason` ∈ `"end of range"`, `"scan limit reached (100000 messages)"`, `"match limit reached (500)"`, `"cancelled"`.
  - `record MessageView(int partition, long offset, Instant timestamp, Decoded key, Decoded value, List<HeaderView> headers)`
  - `RegexMatcher`: `enum Result { MATCH, NO_MATCH, TIMEOUT }`; `static Result find(Pattern p, String text, Duration timeout)` — wraps `text` in a `CharSequence` whose `charAt` throws when the deadline passes.
  - `MessageSearchService`: `Multi<SearchEvent> search(Credentials, SearchRequest)`
  - Routes: `GET /topics/{name}/messages` (tab: form with partitions, From/To (default now-1h → now, from `search.defaultRange`), "Seek by offset" toggle, key regex, value regex, Search button, Live/Tail toggle). `GET /topics/{name}/messages/search` → `text/event-stream`, htmx SSE events `match` (row HTML), `progress`, `done`. Closing the SSE connection cancels the Multi (consumer closed). `GET /topics/{name}/messages/{partition}/{offset}` → detail (key, value with highlight.js, headers, partition, offset, timestamp, explanation per key/value, "Decode as" select → `GET ...?keyAs=TEXT&valueAs=JSON` re-renders).

Search algorithm: for each partition, start = `fromOffset` or `offsetsForTimes(from)` (null → skip partition), end = `offsetsForTimes(to)` (null → `endOffsets`); `assign`, `seek`, poll until every partition reaches its end; decode each record, match regexes against `Decoded.text` (both regexes given → both must match); emit `Progress` every 1000 scanned and on completion; stop at `maxScanned`/`maxMatches`. Runs on a worker thread (`Infrastructure.getDefaultWorkerPool()`), never on the event loop.
